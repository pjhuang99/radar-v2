# 独立「事实核查」入口 — 规划

> 状态：规划中（未开发）。本文件是时评雷达新增独立事实核查入口的权威规划文档，随讨论持续修订。

## 背景与目标

- 财报雷达的「事实核查」只覆盖上市公司新闻/财报核对；用户有大量**跨领域**新闻初稿（商业、时事等）需要核查。
- 目标：在时评雷达新增一个**独立入口**，进去后 **左栏粘贴待核查文字，右栏「溯源核查」按钮 + 结果**，UI 参考财报雷达「事实核查」页。
- 现状：时评雷达的溯源核查引擎**已经完整存在**，只是焊死在「写稿 → 草稿 → 溯源核查」链里。要做的是**解耦 + 复用**，而非重写。

## 现状（已核对代码）

- 无路由：单页 App，`writeMode: 'direct' | 'search'` 切换「原料直达 / 选题检索」（`App.tsx:329`，toggle 在 `:2463`）。
- 引擎四件套都在 `src/App.tsx`，后两件是纯函数：
  - `extractFactCheckQueries(title, body)` —— 从文章抽核查查询词
  - `performAutoRetrieval(queries)` —— 新浪 + DeepSeek 并行检索 → 去重 → 选 ≤3 → `/api/scrape` 抓全文
  - 事实核查 LLM 提示词（「职业事实核查员」）+ `parseFactCheckReport` / `parseSourceLinks` —— 出 ERR/WARN/OK
- 后端三个接口已存在：`/api/deepseek-search`、`/api/sina-search`、`/api/scrape`（`api/index.ts` Vercel 自包含 + `api/_lib/shared-routes.ts` dev 双份）→ **无需新增任何路由**。

## 方案（分阶段）

### 阶段 1：抽引擎 `src/lib/factcheck.ts`
把四件套搬进去并参数化。核心改动只有一处：把「待核查文章」从固定读 `draftTitle/draftBody` 改成函数入参；「原始参考素材」从必填变可选（独立核查时没有参考链接）。

**authority 逻辑集中并改造**（采纳顾问 #2，打折）：
- `finalAuthority = max(deepseekAuthority, whitelistAuthority)`（**取高合并**，不再 `App.tsx:1844` 直接覆盖）。
- 白名单 `AUTHORITY_WHITELIST` 已存在（`config/sources.ts`），确认补上硬兜底类：巨潮/交易所/证监会/政府 `.gov.cn`/央媒（新华社、人民日报、央视）—— 这几类**不得**交给模型判断。
- ⚠️「记录 DeepSeek 给分理由」**做不到**：DeepSeek Search 返回 `authority`(整数)/`rerank_score`/`site_name` 等，**无理由文本**；退化为记录原始 `authority` 值 + `site_name` 作为可抽检解释。

### 阶段 2：新面板 `src/components/FactCheckPanel.tsx`
照抄 `TopicSearchPanel` 的左输入/右结果结构：
- 左栏：多行 textarea 粘贴待核查文章（必填）+ 可选「标题」+ 可选「补充核查链接」。
- 右栏：「溯源核查」按钮 → 跑 pipeline → 结果（复用现有 ERR/WARN/OK 卡片 + 自动检索信源列表的 JSX）。
- 空文章 / 检索无结果时给明确提示（对齐财报雷达「空结果不编造」）。

### 阶段 3：入口（已拍板）
- **位置**：顶部 masthead 右侧，**RSS 订阅按钮左侧**（`App.tsx:2317` 的 flex 容器，在 `:2318` RSS 按钮前插入）。
- 形态：顶栏独立按钮，点击进入独立事实核查视图（不占 mode switch 的「原料直达/选题检索」）。

### 阶段 4：报告协议升级（采纳顾问 #5/#6/#7/#8/#9）
- **输出二维**：核实状态 `VERIFIED / CONTRADICTED / UNVERIFIED / DISPUTED` × 风险 `高/中/低`。
  - UNVERIFIED → 处置「删或改存疑」；DISPUTED → 「呈现多方」；CONTRADICTED → 「必改」。
- **断言级标签**：每条打 `claimType`（事实/数字/引述/观点/因果）+ `asOf` 时间锚点。
- **因果/归因打 `INFERENCE`**：只输出「事实部分属实，因果关系未获信源支持」，不硬判 ERR/OK。
- **粒度到句子**（折中 #6）：报告结论下放到句子/断言，每条指向具体原句；但**检索不做逐断言**（成本爆炸），仍走「少查询 → 少信源 → LLM 通读全文 + 信源」。
- **DISPUTED 加权呈现**：输出冲突双方各自最强信源 + 发布时间 + 权威分，不做多数投票。
- **数字断言容差比对**（非字符串相等）+ 附命中原文片段（`/api/scrape` 已抓全文，可引用命中句）。

### 阶段 5：独立性聚类（采纳顾问 #1）
检索结果按 **域名 + 标题相似度（Jaccard）+ 发布时间** 聚类，转载归并到原始稿再算「独立信源覆盖」。防「十家转载被误读为十方印证」。美股雷达已有 Jaccard≥0.5 聚类的现成经验可复用。

### 阶段 6（可选，建议第二步）：draft 流程切共享模块
草稿内溯源核查改调 `src/lib/factcheck.ts`，消除两份实现 drift，行为不变。

## 延后清单（不做，或 v2 再做）

- 别名归一引擎（江淮=安徽江淮汽车集团、尊界=MAEXTRO）—— 等真实命中率掉下来再补。
- 数字规范化引擎 —— v1 只做数字断言容差比对。
- 逐断言独立检索 —— 成本爆炸，不做。

## 成本与风险

- 每次核查 ≈ ≤6 查询 × 2 引擎 + ≤3 次抓全文 + 1 次 LLM，与现有溯源核查同量级。
- 后端零改动，Vercel 部署无新坑（不新增路由）。
- 风险集中在 LLM 提示词小改 + 查询抽取的跨域效果，需实稿验证。

## 验证方式

- 类型检查 + 构建：`npm run lint` / `npm run build`。
- 本地 `PORT=3002 npx tsx server.ts`，用 Playwright（全局 `@playwright/cli`）截图验证：入口按钮位置、左贴文 → 右结果、ERR/WARN/OK + 二维状态渲染、DISPUTED 多方呈现、空结果提示。
- 拿 2–3 篇真实跨领域初稿（商业 1 篇、时事 1 篇）实测查询命中与结论质量。
